# 06 维护与验收

## 每次提交前

### 1. 密钥扫描（全工作树，含未跟踪与 .md）

```bash
# 有 gitleaks（推荐）
gitleaks dir . --redact --no-banner

# 没有 gitleaks
grep -rInE "api[_-]?key|secret|passw(or)?d|token" . \
  --exclude-dir=.git --exclude-dir=node_modules --exclude-dir=.venv \
  --exclude="*.example"
```

- 只排除 `*.example` 占位模板，且必须人工确认里面没有真实值。
- `git grep` 只查已跟踪文件，首次提交前会假通过，不要用它做验收。
- 发现泄漏：先轮换密钥，再用 `git filter-repo` 清理历史，最后强推。

### 2. 忽略规则

```bash
git status --ignored --short
```

确认 `config.json`、`.env`、日志、sqlite、zip 都在忽略列表里，且没有被强制加入暂存区。

### 3. 技能格式

- 每个 `skills/<name>/SKILL.md` 的 frontmatter 有 `name` 与 `description`；
- `name` 与目录名一致；
- 第三方目录有 `LICENSE` 与 `UPSTREAM.md`，且 `UPSTREAM.md` 的 hash 与文件一致。

### 4. MCP 模板

- `mcps/<name>/mcp.json.example` 是合法 JSON；
- 不含真实 token、账号、用户名；
- 字段与 `~\.zcode\cli\config.json` 的现有条目同形状。

### 5. 项目测试

`projects/zcode-persistence` 的标准测试（在项目目录下执行）：

```bash
python -I tools/selftest_proxy_429.py
python -I tools/selftest_stream.py
python -I tools/selftest_watch.py
```

三套全部通过才算改完；细节见项目 `文档/04-测试记录.md`。

## 提交后

```bash
git count-objects -vH        # 仓库体量，目标 < 10 MB
git log --oneline -5
git status
```

- 体量检查必须在首次提交之后做；提交前对象数为 0，查不出问题。
- 单文件不得超过 100 MiB；二进制一律走 Releases。

## 发版检查表

- [ ] `VERSION` 与 `CHANGELOG.md` 已更新
- [ ] 项目测试全部通过
- [ ] 发行包生成，sha256 已记录
- [ ] 打 tag：仓库 `vX.Y.Z`，项目 `proj-<name>-vX.Y`
- [ ] Release 上传发行包（与本地 sha256 一致）
- [ ] 需要时上传历史导入包，tag 为 `proj-<name>-vX.Y-history`
- [ ] README 索引表已更新（只改链接与状态）

## 定期检查（建议每月）

1. 上游技能是否有安全/行为修正；有则单独提交升级，更新 `UPSTREAM.md`；
2. `~\.zcode\skills` 与仓库是否漂移（hash 对比）；
3. MCP 服务是否仍能连接；
4. 仓库体量、过期分支、未合并 PR；
5. 许可证与来源登记是否仍然准确。
