# 02 收录规范

## 技能（skills）

### 准入条件

1. 有明确的使用场景：`description` 写“什么时候用”，不是宣传语。
2. 目录自包含：不依赖同仓库其他技能的相对路径。
3. 第三方内容有明确许可证（MIT / Apache-2.0 等）；无许可证的只登记链接，不复制。
4. 能在当前 ZCode 版本加载：`SKILL.md` 的 `name` 与目录名一致。

### 目录内容

| 文件 | 必需 | 说明 |
|---|---|---|
| `SKILL.md` | 是 | frontmatter + 正文 |
| `LICENSE` | 第三方必需 | 原样保留，含版权行 |
| `UPSTREAM.md` | 第三方必需 | 来源、hash、导入日期、本地改动 |
| `references/` | 否 | 参考材料，随技能一起同步 |

### `SKILL.md` frontmatter

```yaml
---
name: <与目录名一致>
description: <什么时候用；写触发条件与边界，不写宣传语>
---
```

### `UPSTREAM.md` 模板

```markdown
# 来源

- 上游仓库：https://github.com/<owner>/<repo>
- 上游路径：skills/<name>
- 导入方式：已安装快照（非 HEAD）
- 本地文件：SKILL.md sha256=<...>
- 上游 blob：<sha 或"未记录">
- 导入日期：2026-11-01
- 许可证：MIT（见同目录 LICENSE，含 Copyright 行）
- 本地改动：无 / 具体列出
```

### 第三方内容的处理

- **收录已安装快照，不直接拉上游 HEAD**：正在用的版本是已验证可用的；上游可能已改。
- **不用 git submodule**：ZCode 加载的是普通目录，submodule 会留嵌套 `.git`，
  同步与备份都容易出错。用 vendor + `UPSTREAM.md`。
- 升级第三方技能：单独提交，更新 `UPSTREAM.md` 的 hash 与日期，在提交信息里写清差异。

## MCP（mcps）

### 准入条件

1. 自写服务，或正在使用的第三方服务（后者只收配置模板）。
2. 不把第三方源码复制进仓库；只记录包名、版本、启动命令。
3. 模板中不出现任何真实 token、账号、路径中的用户名。

### 目录内容

| 文件 | 必需 | 说明 |
|---|---|---|
| `README.md` | 是 | 用途、安装、启动、认证方式、故障排查 |
| `mcp.json.example` | 是 | 与真实 `mcp.servers.<name>` 同形状的模板 |
| `.env.example` | 否 | 有环境变量时提供占位符 |
| `src/` | 自写服务 | 第三方服务不要放 |

### 模板与真实配置

真实配置在 `C:\Users\<用户>\.zcode\cli\config.json` 的 `mcp.servers.<name>`，
**永远不进库**。模板示例：

```json
{
  "mcp": {
    "servers": {
      "<server-name>": {
        "type": "stdio",
        "command": "<解释器绝对路径>",
        "args": ["<入口脚本绝对路径>"],
        "timeoutMs": 60000,
        "env": {
          "API_KEY": "${API_KEY}"
        }
      }
    }
  }
}
```

注意：

- **ZCode 不会展开 `${VAR}`**。占位符由部署脚本在落盘前替换；没有脚本时手工替换。
- `env` 是可选项，不是所有服务都需要。
- ms365 走 OAuth 令牌缓存（`%APPDATA%\ms-365-mcp-server\.token-cache.json`），
  不需要在配置里写密钥。

## 项目（projects）

### 准入条件

1. 有独立生命周期：自己的版本号、文档、测试与发行包。
2. 源码可提交，运行产物可排除。
3. 有明确许可证或明确标注“私有/未授权”。

### 目录内容

```text
projects/<name>/
├─ README.md        索引：一句话 + 版本 + 指向 文档/
├─ src/             可执行源码
├─ tools/           安装/自检/运维脚本
├─ 文档/            当前版文档
└─ 逻辑图/          当前版结构图（Markdown）
```

### 历史与发行

- **不建 `历史/`**：旧版本用 tag 固定，发行包上传 Releases。
- 迁移前已经存在的本地历史，打包为 `*-history-import.zip` 挂到
  `proj-<project>-v<version>-history` 的 Release，并在
  [04-迁移记录](04-迁移记录.md) 登记 sha256。
- 发行包命名与本地一致，上传前比对 sha256。

## 归档

项目停止维护时：

1. 在 `projects/README.md` 的状态列标 `archived`；
2. 打最后一个 tag，Release 保留；
3. 不删除目录与历史；如需移出仓库，先确认 tag 与 Release 完整。
