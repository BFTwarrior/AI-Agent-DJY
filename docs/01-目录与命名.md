## 命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 仓库 | 用户指定 | `AI-Agent-DJY` |
| 技能目录 | 小写 kebab-case，与 `SKILL.md` 的 `name` 一致 | `code-review-and-quality` |
| MCP 目录 | 小写 kebab-case，与 `mcp.servers` 的键一致 | `ms365` |
| 项目目录 | 小写 kebab-case | `zcode-persistence` |
| 仓库文档 | `NN-主题.md`，两位编号 | `03-部署与同步.md` |
| 项目文档 | 沿用项目自己的编号，不强行统一 | `00-总览.md` |

约束：

- 不用空格、下划线、中文目录名；中文只出现在文件名与正文里。
- **唯一例外**：项目内部按用户约定保留 `文档/`、`逻辑图/`（见第 4 节）；仓库级目录仍用英文。
- 目录名一旦发布就不要再改：改了要同步更新所有链接、`UPSTREAM.md` 与部署脚本。
- 同一个名字只允许一种大小写写法（Windows 与 git 对大小写敏感度不同）。

## 项目内部约定

- `src/`：可执行源码。
- `tools/`：安装、自检、运维脚本（不是运行时代码）。
- `文档/`：当前版文档；旧版不在仓库里重复存。
- `逻辑图/`：当前版结构图，统一用 Markdown；XMind 原件放 Releases 或本机。
- 项目 `README.md` 只做索引：一句话说明 + 版本 + 指向 `文档/` 的链接。

## tag 规范

| 对象 | 格式 | 示例 |
|---|---|---|
| 仓库自身 | `v<major>.<minor>.<patch>` | `v0.1.0` |
| 单个项目 | `proj-<project>-v<major>.<minor>` | `proj-zcode-persistence-v0.2` |
| 项目导入前历史 | `proj-<project>-v<version>-history` | `proj-zcode-persistence-v0.1-history` |

- 仓库 tag 与项目 tag 分开，避免“这次发布的是哪个包”说不清。
- Release 资产命名与本地发行包一致，上传前比对 sha256。

## 分支与提交

- 默认分支 `main`，不直接推送；改动走分支 + PR（个人库也执行）。
- 提交信息：`<type>: <中文简述>`；type 取 `feat` / `fix` / `docs` / `chore` / `import`。
- 导入第三方内容用 `import:`，正文写来源仓库、路径、许可证。
