# 03 部署与同步

## 三层链路

```text
仓库（源）
  skills/<name>/
        │ ① 安装（需管理员）
        ▼
C:\Program Files (x86)\AI\AI-Agent-DJY\skills\<name>\
        │ ② 同步（普通权限）
        ▼
~\.zcode\skills\<name>\SKILL.md          ← ZCode 实际加载
```

MCP 同理：

```text
仓库 mcps/<name>/（模板）
        │ ① 自写服务安装到 AI 目录
        ▼
C:\Program Files (x86)\AI\<server-name>\
        │ ② 渲染模板 + 备份 + 合并
        ▼
~\.zcode\cli\config.json  →  mcp.servers.<name>
```

项目不复制：`projects/<name>/` 就是开发目录，`git pull` / `commit` / `push` 即可。

## 为什么需要安装层

你的机器规则是“技能和 MCP 装到 `C:\Program Files (x86)\AI`，并建具体文件夹”。
现有 `AI\addyosmani-agent-skills` 与 `~\.zcode\skills` 的 `SKILL.md` 完全一致，
说明运行时用的是副本，AI 目录是安装/留档层。新仓库沿用这个结构：

- `AI\AI-Agent-DJY\skills\<name>`：安装层，换机器时从这里恢复；
- `~\.zcode\skills\<name>`：运行时副本，ZCode 只读这里；
- 现有 `AI\addyosmani-agent-skills` **不删除**，作为上游快照与回滚点。

## 同步规则（手工版，脚本待补）

当前仓库尚未实现自动脚本，按以下规则手工执行；实现脚本时必须遵守同一套规则。

### 技能

1. 对比：`sha256` 仓库 `SKILL.md` 与 `~\.zcode\skills\<name>\SKILL.md`。
2. 备份：把目标目录复制到 `%TEMP%\AI-Agent-DJY-backup-<时间>\`。
3. 覆盖：只复制 `SKILL.md`、`references/`、`LICENSE`、`UPSTREAM.md`。
4. 不删除目标里多出来的目录；多出来的先报告，人工确认。
5. 校验：再次对比 hash；不一致就回滚。

### MCP

1. 备份 `~\.zcode\cli\config.json` 为 `config.json.bak-<时间>`。
2. 只改 `mcp.servers` 下对应条目；**保留其他未知字段**。
3. 占位符替换后再写盘；写盘用临时文件 + `os.replace`。
4. 任一步失败：用备份回滚，并报告失败原因。
5. 验证：重启 ZCode 后确认该 server 仍能连接；`github`、`ms365` 不能因改配置失效。

## 禁止事项

- 不直接改 `~\.zcode\skills\` 或 `config.json` 作为“长期方案”；临时调试后要回写仓库。
- 不在仓库里保存真实 `config.json`、token cache、`.env`。
- 不同步时不做“镜像删除”：目标里多出来的技能可能是别的来源，删了会丢能力。

## 回滚

| 场景 | 回滚方式 |
|---|---|
| 技能同步后行为异常 | 从 `%TEMP%\AI-Agent-DJY-backup-<时间>` 复制回目标 |
| 安装层被覆盖 | 从 `AI\addyosmani-agent-skills` 或备份恢复 |
| MCP 配置写坏 | 用 `config.json.bak-<时间>` 覆盖回去，重启 ZCode |
| 项目升级失败 | `git checkout <上一个 tag>`，或从 Releases 取旧包 |

## 换机器恢复顺序

1. clone 仓库到 `<workspace>\AI-Agent-DJY\repo`；
2. 按 `skills/*/UPSTREAM.md` 校验第三方许可证与来源；
3. 把技能复制到 `AI\AI-Agent-DJY\skills\`，再同步到 `~\.zcode\skills\`；
4. 按 `mcps/*/README.md` 安装服务与配置，密钥从本机环境变量注入；
5. 需要项目时直接使用 `projects/<name>/`，发行包从 Releases 取。
