# 架构图（V0.2 正式版）

> 构建线 0.4.0。参数与语义以 `发行/Zcode-Persistence-V0.2-正式版/src/` 里的代码为准，
> 本文只画关系，不重复全部细节。

## 三条链路

```
┌────────────────────────────────────────────────────────────────────┐
│ ZCode 客户端                                                        │
│                                                                    │
│  模型请求 ──► retry_proxy.py (127.0.0.1:8787) ──► 上游中转          │
│               │  /ap/... → upstream-a.example.com/v1                       │
│               │  /cm/... → upstream-b.example.com/v1                 │
│               └─ 失败在"尚未回写任何字节"之前自动重发                │
│                                                                    │
│  Bash 工具失败 ──► PostToolUse（主）                                │
│                └─► PostToolUseFailure（兜底，本客户端不派发超时/中断）│
│                          │                                         │
│                          ▼                                         │
│                    retry_hook.py                                   │
│                          │  stdout JSON: {"additionalContext": …}  │
│                          ▼                                         │
│                    模型看到建议，自行决定是否原样重试                 │
│                                                                    │
│  会话启动 ──► SessionStart ──► ensure_proxy.py ──► 端口空则拉起代理  │
│                                                                    │
│  会话报错（红点）──► error_watch.py ──► outlook MCP ──► 邮件        │
│                     （默认关闭；last_outcome=error 才报）            │
└────────────────────────────────────────────────────────────────────┘
```

| 链路 | 触发 | 产物 | 能否真正重发 |
|---|---|---|---|
| 钩子 | Bash 调用失败 | 一条注入上下文的重试建议 | 否，只能建议 |
| 代理 | 一次模型请求失败 | 重发后的响应 | 是 |
| 自启动 | 会话开始 | 确保代理在跑 | — |
| 报错汇报 | `session.last_outcome=error` | 一封含原因的邮件（默认关闭） | 否，只汇报 |

## 代理重试状态机

```
请求 ──► 读完整 body（兼容 chunked）──► UA 兜底 ──► 解析 stream 判断流式
   │
   ▼
主循环（时间窗 started .. started+180s，RETRY_INTERVAL=20s 一次尝试）
   ├─ 每次尝试：建连 10s → 发送 body 90s → 等首字节 30s
   ├─ 失败判定：连接异常 / 任何非 2xx / 静默 30s 无字节
   ├─ 失败后：等 max(20s, Retry-After≤60s) 再试；下一次落在窗口外就收尾
   ├─ 窗口到期且无在飞尝试 → 收尾（MAX_ATTEMPTS=200 只是防跑飞保险丝）
   └─ 心跳：连续 80s 无上游输入 → 写 SSE 注释行 `: keepalive`，
            之后每 80s 一条，不设上限（独立时钟，不等尝试边界）
   │
   ├─ 成功 → 回写响应头 → 边读边 flush
   │    ├─ 流中途断 → 结束，不补 chunked 终止块（否则客户端误以为完整）
   │    └─ 正常结束 → 记 ok
   └─ 窗口结束仍失败 → 流式：SSE error 事件；非流式：503 + OpenAI 形状错误体
```

**关键约束**：一旦开始向客户端回写字节就不能重试（会重复内容），所以重发只发生在
"首字节之前"。心跳是为了让客户端 95 秒首字节超时不误伤长等待。

## 钩子判定顺序

```
非 Bash 工具 ──► 放行（matcher 已限定 Bash，这里是双保险）
  ↓
失败判定只看硬信号：exitCode ≠ 0 / timedOut / cancelled|interrupted / status ∈ {failed,error,failure}
（不看命令原文；绝不写成 status != "completed"，那会把 status=success 误判成失败）
  ↓
同 toolCallId 已建议过 → 跳过（两个事件可能各触发一次）
  ↓
UPSTREAM_PATTERNS 命中（上游没产出类）
  └─► 建议：先 sleep 180 再原样重试（该命令超时设到 200000ms 以上）
  ↓
其它任何失败
  └─► 建议：立刻原样重试
  ↓
计数到 3 次 → 不再建议，要求模型向用户说明卡点
```

**没有错误类型白名单**：v0.3.x 的 FATAL 过滤已删除，代理侧同样对任何非 2xx 重发。
这是用户的明确规格，改回来等于违背需求。
