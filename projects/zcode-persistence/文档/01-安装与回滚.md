# 01 安装与回滚

## 前置检查

```bash
python --version          # 需要 3.9+
```

确认 ZCode 的两个配置文件存在：

- `~/.zcode/cli/config.json`
- `~/.zcode/v2/provider_config.json`

Windows 下 `~` 是 `C:\Users\<你的用户名>`。

---

## 安装模式 A（只装钩子）

```bash
python tools/install.py
```

安装器会做四件事：

1. 把 `src/` 下四个脚本（retry_hook / retry_proxy / ensure_proxy / error_watch）复制到 `C:\Program Files (x86)\AI\Zcode-Persistence\`
2. 在 `config.json` 的 `hooks.events.PostToolUse` 里追加主钩子（`matcher: "Bash"`），并在 `hooks.events.PostToolUseFailure` 追加同脚本作为兜底
3. 在 `hooks.events.SessionStart` 里追加一条自启动检查
4. 把安装信息写入 `install-state.json`

重复运行不会重复添加。每次改动前自动备份，文件名形如 `config.json.bak-20261030-140631`。

**验证**：

```bash
python tools/doctor.py
```

应看到 `PostToolUse 钩子（主）: 已注册`、`PostToolUseFailure 钩子（兜底）: 已注册`、`hooks.enabled: True`。然后**新开一个 ZCode 会话**（钩子清单在会话启动时快照，旧窗口不会生效）。

---

## 安装模式 B（钩子 + 代理）

```bash
# AP 通道
python tools/install.py --with-proxy --provider-id new-provider

# upstream-b 通道
python tools/install.py --with-proxy --provider-id new-provider-3

# 地址无法识别时必须显式指定前缀
python tools/install.py --with-proxy --provider-id my-relay --proxy-prefix ap
```

额外的动作：把该 provider 的 `baseUrl` 改成本地代理地址。前缀按原始地址自动识别
（含 `upstream-b.example.com` → `/cm`，含 `upstream-a.example.com` → `/ap`）；识别不出来会直接报错退出，
不会猜。

**为什么必须先确认 provider id**：安装器只改你点名的那一个，避免误伤别的通道。查看现有 id：

```bash
python - <<'EOF'
import json, os
p = os.path.join(os.path.expanduser("~"), ".zcode", "v2", "provider_config.json")
for r in json.load(open(p, encoding="utf-8"))["config"]["providerConfigRules"]["providerRules"]:
    print(r["providerId"], "->", r["config"]["api"]["baseUrl"])
EOF
```

**验证顺序**：

1. `python tools/doctor.py` → 应显示"provider 走代理"和"代理端口 8787 监听中"
2. `python src/retry_proxy.py`（前台跑一次，看是否有报错）
3. 另开终端 `curl http://127.0.0.1:8787/ap/v1/models` —— 返回 401/404 都算正常（说明代理在转发），连不上才是问题
4. 新开 ZCode 会话，随便问一句，能正常回复即成功

## 回滚

### 一级：只撤销配置，脚本留着

```bash
python tools/uninstall.py
```

会移除三处钩子条目（`PostToolUse`、`PostToolUseFailure`、`SessionStart`）、把 provider 地址还原（仅当它仍指向代理时），脚本文件保留。改动前同样备份。

### 二级：连脚本一起删

```bash
python tools/uninstall.py --purge
```

### 三级：用备份硬还原（安装器本身也坏了时）

```bash
ls ~/.zcode/cli/config.json.bak-*          # 找出安装前的备份
cp ~/.zcode/cli/config.json.bak-<时间戳> ~/.zcode/cli/config.json
cp ~/.zcode/v2/provider_config.json.bak-<时间戳> ~/.zcode/v2/provider_config.json
```

> 注意：`cp` 会覆盖，执行前确认备份文件的时间戳早于你最后一次手动改动，否则会丢掉后来的修改。

---

## 只想起个临时效果？

不想装钩子，只想临时验证代理能不能用：

```bash
python src/retry_proxy.py          # 前台运行，Ctrl+C 停止
```

然后用 curl 直接打 `127.0.0.1:8787/ap/v1/chat/completions`，**不要**改 provider 配置。验证通过再正式安装。
