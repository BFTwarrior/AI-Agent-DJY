## What 0.1.8 means

- Workspace is resolved per tool call, not frozen at MCP startup: explicit `workspace`, session `agent_teams_workspace use`, `AGENT_TEAMS_WORKSPACE`, a session with team config/discovery, the saved target, the newest live daemon, then the startup folder. One conversation can switch between project A and B; a ZCode default workspace with no team config falls back to the recent daemon instead of failing on `not a git repository`.
- `agent_teams_workspace` adds `current/list/use/auto`; all tools accept an optional `workspace`. The saved target never overrides a session that owns team config. Auto-start only runs where team config exists.
- The SessionStart hook also fires when a live daemon exists, so a bare host session gets the panel startup rule. The standalone panel window (`panel --window`, `npm run panel:window`, `open-panel.cmd`, `agent_teams_view {window:true}`) uses Edge/Chrome `--app`; browser preference is Edge, then Chrome, then the OS default.
- Installed-server probes verified default-workspace fallback, A/B switching across two daemons, the hook payload, and a separate Edge app window. Details: `docs/status/STATUS.md` and `docs/verification.md` section 29.
