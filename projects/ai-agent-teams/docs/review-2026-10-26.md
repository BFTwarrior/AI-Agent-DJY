## 0.6 review round (independent subagent, 2026-10-26)

The v0.6 first version was reviewed independently. Nine P0s were reproduced with the fake adapter and temporary git repositories, then fixed:

1. Member-scoped tokens and admin-only HTTP routes; members cannot relicense/approve/merge via the daemon API. CLI and protocol footers carry a member-scoped token. **Limit:** daemon and members run as the same OS user, so a member that reads the discovery file can still recover the admin token; true isolation needs a separate OS user/container.
2. Terminal tasks reject further updates; result fields are whitelisted; `attemptId` is cleared on close; plan/task team ids are forced from the route context.
3. Failed and stalled dispatches close their attempt rows and clear `reassigning`, so a transient failure no longer wedges the task/member.
4. Worktree tasks require `mergeState=merged` for both delivery audit and settlement.
5. Integration branches are unique per task/attempt; rejected/unknown branches are discarded and can no longer contaminate a later task; fast-forward verifies the expected cherry-pick.
6. `task.base` is ignored; merge base comes from the configured team base branch, and `mergeBranch` cannot equal a base branch.
7. Contractors run through a CLI adapter (waits for the result), receive plan/read-only tool restrictions, are time-clamped, and are process-tree killed. Protocol member sessions still rely on prompt-scoped tokens rather than per-session env.
8. Reviewer independence compares `assigneeId` when available; a relicensed member cannot review its own work.
9. Only structured JSON can return a `pass` verdict; plain-text ambiguity is treated as unknown.

Remaining known gaps after this round:

- Same-user admin-token discovery (see item 1); use a separate OS user or container for a real boundary.
- `toolPolicy`/`pathScope` are not yet enforced by the protocol session; CLI contractors get disallowed tools, but member sessions rely on prompts plus task scope gates.
- Task `verify` commands run on the daemon host, not in a container; do not run untrusted task contracts without sandboxing.
- Live protocol `session/compact`/`session/resume` and app-server RSS release are unverified.
- Real-model E2E, actual container execution, multi-host load, and web/native UI remain open.
